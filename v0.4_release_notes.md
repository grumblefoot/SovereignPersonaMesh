# Sovereign Persona Mesh (SPM) - v0.4 Release Notes

> **Draft.** v0.4 is in testing and not yet released. These notes are finalised when `v0.4` is
> tagged.

## What's New in v0.4

v0.4 makes SPM's core promise real: each character now knows only what it perceived. Memory
recall works, the world is tracked per chat, and the proxy schedules every model call so chat
stays responsive. It also adds support for scenario cards and group chats.

### Perception and gating

* **Per-character history:** each character's prompt is built from what *they* perceived
  (stored per turn), not from the raw chat transcript. A character behind a closed door hears
  muffled sounds or nothing, and its history shows the gap.
* **Message conventions:** `"speech"`, `*actions*`, `'private thoughts'` (never heard by
  anyone), `**directions to the AI**` / `((...))` / `[OOC: ...]`, and explicit tags such as
  `[whisper:Name]`, `[move:place]` and `[shout]`. Anything else is treated as speech.
* **Spatial rules:** speech is clear up to 5 ft and muffled up to 15 ft; closed doors, metal and
  solid walls block sound; shouting carries further; whispers reach bystanders only as a murmur.
* **Group chats:** characters joining a group are placed in the scene, and an author's direction
  goes only to the first character who replies.

### World engine

* **One world per chat:** rooms, positions and doors are kept separately for every chat and
  survive restarts. Each turn advances the chat's clock once, and regenerating doesn't advance it.
* **Model-proposed changes, validated:** after each reply, a small separate model call reads
  the exchange and lists location changes (new rooms, who moved where). Each change must quote
  the line that shows it, and SPM checks the quote in code: it must be narration, not dialogue,
  and must describe someone going somewhere. Then the usual validator applies it.
  `gm_actions_mode` sets this to `full`, `move_only` or `off`; the default, `auto`, enables it
  for local models only.
* **Starting scene:** a chat starts in a template matched to the card (or `[scene:KEY]`), or an
  empty world the story builds out.

### Memory and lore

* **Real embeddings:** memories are recalled by meaning through any OpenAI-compatible
  embeddings endpoint (default `Qwen3-Embedding-0.6B-GGUF-Q8_0`), with text search as a
  fallback. Switching embedding models is safe; `scripts/reembed.py` moves old memories over.
* **Lore per chat:** rules learned in a chat stay in that chat, pending until you approve them
  in the admin dashboard; you can promote a rule to canon so it applies to every chat. Reworded
  duplicates are skipped.
* **Token budget:** memories, lore and history are fitted to the model's context window. The
  oldest history goes first, and the chat's opening (greeting, first exchange) is always kept. A card
  too large for the window is refused with a clear notice instead of being cut.

### Scenario cards and characters

* **Narrator mode:** cards that voice a whole world ("... RPG World", "Narrator", "Game
  Master"…) are detected from their name and treated as a narrator that follows you everywhere.
  Override it per chat in the admin dashboard.
* **Character sheets:** a block of `Name: / Age: / ...` lines is kept as your character's setup
  (shown to the narrator every turn), not as dialogue, and its name is recognised as you.
* **Greetings:** the card's opening message, or the alternate opening you swiped to, is part of
  the chat's history.

### Reliability

* **Model scheduling:** one queue for every model call. Your chat turn always goes first,
  background work (lore review, memory consolidation) yields to it, and regenerating replaces
  the turn in progress. SillyTavern's own background requests no longer interrupt your turn.
* **No planning text in replies:** SPM no longer asks the model to write a hidden planning
  block before each reply. `reasoning_mode` (admin dashboard, "Model Reasoning") chooses:
  `none` (default: no hidden reasoning, fastest), `native` (the model server's own thinking,
  kept private; costs extra tokens), `auto` (native when a local server supports it) or
  `prefill` (the v0.3-style scratchpad). Thinking switches are sent to local servers only.
  If a model still writes planning text, it is stripped, and a reply that is only planning is
  withheld with a notice.
* **Clear failures:** if the model server is down or busy, you get a notice and nothing is
  saved, rather than an invented reply. If the world engine is down, the turn continues without
  gating.

### Model servers

* **Any OpenAI-compatible server:** set `BACKEND_LLM_URL` (Lemonade by default; LM Studio on
  another machine has been tested). Model names are matched across naming schemes.

### SillyTavern integration

* **SPM Chat ID extension** (`st_extension/SPM-Chat-ID/`): gives every chat a stable identity
  and tells SPM the generation type and turn count. See
  [docs/st_extension_setup.md](docs/st_extension_setup.md).
* **Going back in a chat** (deleting messages or swiping to another opening) makes SPM forget
  the abandoned turns.
* **Imported chats and chats started before SPM:** the earlier turns are used in the next
  reply at once and recorded for each character when the model is idle. In group chats each
  line goes to the character who spoke it.
* **Utility generations** (impersonate, summaries) are passed through untouched and never
  saved.

### Admin dashboard

* World map per chat, memory and lore inspector, recall scores, a live thought stream, and
  settings for embeddings, token budget, GM actions, model reasoning and narrator mode. The model queue is
  available at `GET /admin/api/v1/scheduler`.

### Upgrading from v0.3

1. Apply the database migrations: `.venv/bin/python scripts/apply_migrations.py`.
2. Install the SillyTavern extension and add the four `X-SPM-*` headers (see the README).
3. Optional: turn off SillyTavern's Summarize extension. SPM keeps its own memories and strips
   Summary and Author's Note blocks from character prompts anyway (setting
   `st_passthrough_shared_notes` keeps them), so Summarize only adds background model calls.
4. Python 3.13 or newer is required; runtime dependencies are now six packages
   (`requirements.txt`).

### Known Issues

See [known_issues.md](known_issues.md). In short: no authentication (run SPM on a trusted
machine or network); occasional turns cut off a few seconds in (regenerate works); scenario
NPCs aren't tracked as separate characters yet.
